# myOps — Project Plan

## Overview

myOps is a unified web interface for self-hosted Gitea repositories and Drone CI/CD pipelines. It acts as a dashboard layer that aggregates data from both services through their official Go SDKs, providing a single-pane-of-glass experience for developers.

## Authentication

### Gitea OAuth2 Provider

myOps delegates authentication to Gitea's built-in OAuth2 provider — no separate user management needed.

### Flow

```
1. Admin registers myOps as an OAuth2 application in Gitea (Settings → Applications)
   → Obtains ClientID / ClientSecret
2. User visits myOps → redirected to Gitea authorization page
3. User approves → Gitea redirects back with an authorization code
4. myOps exchanges the code for an access token (via golang.org/x/oauth2)
5. myOps identifies the user via the token (GET /api/v1/user), creates a session
```

### Drone Authorization Strategy

The Gitea token is used for Gitea API calls. For Drone, myOps uses a **service-level token** (generated by a Drone admin) that is shared across all myOps users. This avoids requiring each user to configure a separate Drone token, since Drone build views are typically team-shared anyway.

**Future option**: Per-user Drone tokens can be added later if fine-grained build permissions are needed.

### Session Storage

- Server-side sessions (encrypted cookies or in-memory store)
- OAuth2 token is stored in the session, not exposed to the client
- Logout clears the session

## Interaction Model (HTMX)

- **Page navigation**: `hx-get` + `hx-target` + `hx-push-url` for SPA-like transitions
- **Data tables**: `hx-get` with `hx-trigger="change"` for sort/filter — partial table refresh
- **Build logs**: Server-Sent Events (SSE) for real-time log streaming
- **Dark mode**: Alpine.js `x-data` + `localStorage` persistence

## Source Code Browsing

Source files from repositories are displayed in a read-only file viewer with syntax highlighting. The architecture uses an interface-based design so that the rendering backend can be upgraded without touching handler or template code.

### CodeRenderer Interface

```go
type HighlightResult struct {
    HTML    template.HTML  // syntax-highlighted HTML fragment
    Symbols []Symbol       // extracted symbols (Phase C); empty in Phase A
    Err     error
}

type Symbol struct {
    Kind     string // "function", "type", "variable", "class", etc.
    Name     string
    Line     int
    Col      int
    Children []Symbol
}

type CodeRenderer interface {
    Render(filename string, content []byte) (*HighlightResult, error)
    DetectLanguage(filename string) string
}
```

### Phase A — Chroma (Initial)

| Aspect | Detail |
|--------|--------|
| Library | `github.com/alecthomas/chroma/v2` |
| Style | Chroma outputs HTML with CSS classes; a single theme CSS file is served statically |
| Coverage | 200+ languages, auto-detection by filename/extension |
| Symbols | Returns empty `Symbols` slice — handler simply ignores it |
| Integration | Standard `html/template` — rendered HTML is injected directly into HTMX fragments |

```go
// renderer.go — wire time
type Config struct {
    // ... existing fields
    UseTreeSitter bool // false in Phase A, true in Phase C
}

func NewCodeRenderer(cfg Config) CodeRenderer {
    if cfg.UseTreeSitter {
        return NewTreeSitterRenderer()
    }
    return NewChromaRenderer()
}
```

### Phase C — Tree-sitter (Future Upgrade)

| Aspect | Detail |
|--------|--------|
| Library | `github.com/tree-sitter/go-tree-sitter` |
| Grammar | Build per-language `.so` grammar or WASM; bundle as embedded assets |
| Coverage | Focus on commonly-used languages first (Go, Python, YAML, JS/TS, Shell) |
| Symbols | Populates `Symbols` → enables file-outline sidebar, symbol breadcrumbs |
| Fallback | Unsupported languages fall back to Chroma (both renderers coexist) |

```go
type TreeSitterRenderer struct {
    grammars map[string]*sitter.Language
    fallback CodeRenderer // ChromaRenderer for unsupported languages
}

func (r *TreeSitterRenderer) Render(filename string, content []byte) (*HighlightResult, error) {
    lang := r.grammars[ext]
    if lang == nil {
        return r.fallback.Render(filename, content) // graceful fallback
    }
    // Tree-sitter AST → semantic tokens → HTML
}
```

### Upgrade Path (A → C)

```
Phase A:  Handler → CodeRenderer(ChromaRenderer) → HTMX fragment
Phase C:  Handler → CodeRenderer(TreeSitterRenderer) → HTMX fragment
                            ↑ swaps here only; handler sees no change
```

- **Zero handler/template changes**: The `HighlightResult.HTML` shape is identical
- **Zero data model changes**: `Symbols` is additive — Phase A returns empty slice, Phase C fills it
- **Coexistence**: TreeSitterRenderer wraps ChromaRenderer as its fallback for ungrammar'd languages
